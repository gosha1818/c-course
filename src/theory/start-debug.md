## Зачем отладчик

Программа собралась, но выдаёт не то. Угадывать, где ошибка, долго. **Отладчик** позволяет остановить программу на любой строке, выполнять её по шагу и смотреть значения всех переменных. Это главный инструмент программиста — на него стоит потратить один вечер.

## Отладчик Visual Studio за 5 минут

| Клавиши | Действие |
|---|---|
| **F9** | поставить / убрать **точку останова** (красный кружок слева от строки) |
| **F5** | запустить с отладкой; программа остановится на первой точке останова. Повторное F5 — продолжить до следующей |
| **F10** | **шаг с обходом**: выполнить текущую строку целиком, не заходя внутрь функций |
| **F11** | **шаг с заходом**: если в строке вызов твоей функции — войти в неё |
| **Shift+F11** | выйти из текущей функции |
| **Shift+F5** | остановить отладку |

Пока программа стоит на точке останова:
- наведи мышь на переменную — появится её значение;
- окно **«Локальные»** (Отладка → Окна → Локальные) показывает все переменные текущей функции;
- в окно **«Контрольные значения»** можно вписать любое выражение: `a[i]`, `sum / n`, `*p`;
- жёлтая стрелка — строка, которая выполнится **следующей** (ещё не выполнена).

> [!tip] Условная точка останова
> Правый клик по красному кружку → **Условия…** → например, `i == 49`. Программа остановится только на 50-м шаге цикла, а не на каждом.

## Как искать ошибку: метод из 5 шагов

1. **Воспроизведи.** Найди вход, на котором программа ошибается. Чем он меньше, тем лучше: массив из 3 элементов, а не из 50.
2. **Предскажи.** Посчитай на бумаге, какими должны быть переменные после каждой строки.
3. **Сравни.** Пройди программу отладчиком (F10) и найди **первую** строку, после которой значение разошлось с предсказанием.
4. **Исправь** именно эту строку.
5. **Перепроверь** на всех тестах, а не только на одном, — исправление могло сломать другое.

Если отладчика нет под рукой (онлайн-компилятор), помогает **печать промежуточных значений**:

```c
for (i = 0; i < n; i++) {
    s = s + a[i];
    printf("DEBUG: i=%d a[i]=%d s=%d\n", i, a[i], s);   /* убрать перед сдачей! */
}
```

## Типичные ошибки, которые ловит отладчик

| Симптом | Частая причина |
|---|---|
| сумма на один элемент меньше/больше | граница цикла: `<` вместо `<=` или наоборот |
| среднее всегда целое | деление `int / int`: нужно `(double)s / n` |
| в переменной огромное «случайное» число | переменная не инициализирована: забыто `s = 0;` |
| программа «зависает» | условие цикла никогда не становится ложным; или `scanf` не может прочитать букву и цикл крутится |
| программа падает | выход за границы массива, `NULL`-указатель, деление на ноль |

## Полезные онлайн-инструменты

- **[C Tutor](https://pythontutor.com/c.html)** — вставь короткую программу и иди по шагам: видно каждую переменную, массив и стрелки указателей. Лучший способ понять указатели (модуль 4).
- **[OnlineGDB](https://www.onlinegdb.com/online_c_compiler)** — онлайн-компилятор с настоящим отладчиком и вводом с клавиатуры.
- **[Compiler Explorer](https://godbolt.org)** — тот самый сервер, на котором тренажёр проверяет задачи. Показывает ещё и машинный код — интересно посмотреть, во что превращается `for`.

> [!info] Как тренажёр сообщает об ошибках
> - **Ошибка компиляции** — показан текст сообщения gcc с номером строки твоего кода.
> - **Неверный ответ** — показаны вход, ожидаемый вывод и твой вывод.
> - **Ошибка выполнения** — программа упала (например, из-за выхода за границы массива) или работала слишком долго (бесконечный цикл). Код возврата показывается всегда: `return 1;` после сообщения об ошибке ввода — это нормально, если вывод совпал.
